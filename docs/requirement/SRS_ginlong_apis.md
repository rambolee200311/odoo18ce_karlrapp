## 1. 目的

本文定义 BeeSmart Odoo 与锦浪（Ginlong）Solis WMS 之间的数据交换及 Odoo 业务服务集成需求，作为后续需求评审、技术验证、技术设计、实施计划和接口联调的输入。

现有接口资料提供了 10 类业务接口、部分触发规则和字段清单。已确认的接口契约可以先开发并通过本地模拟测试；缺少的 Ginlong 外部资料只阻塞依赖该资料的具体实现和真实环境联调。本文将已知需求、工作假设和待决问题分开记录，不补造 URL、鉴权、HTTP 方法、错误码等未提供的协议事实。

## 4. 系统范围与边界

### 4.1 系统上下文

本范围关注 Solis WMS 与 Odoo 之间的 Ginlong API 业务边界：按各接口方向接收 Solis 请求，或由 Odoo 按已确认契约回传/提供仓库事件及库存信息。接口 03 的方向仅按开发假设 A-003 处理，尚非 Ginlong 确认的接口契约。

V3.1 资料把对端称为“第三方 WMS”；本项目按 A-001 将该角色映射为 BeeSmart Odoo。该映射属于本 SRS v1.0 的冻结系统边界，不表示 Ginlong 已对其他接口细节作出确认。

### 4.2 本范围内

- 接收和发送 Ginlong API 数据，并将 API 数据与 Odoo 现有业务服务及业务记录集成。
- 接收入库单、待出库单、盘点单和物料档案等 Solis 数据，调用现有 Odoo 业务服务完成处理。
- 接收库存查询请求，并调用现有 Odoo 库存服务构造查询响应。
- 通过用户在 Odoo 业务单据上的操作，准备收货确认、入库完成、备货完成、发货完成和盘点完成 Payload，并调用对应 Ginlong 接口。
- 记录请求接收、业务处理及结果回传的独立状态和可追踪结果。
- 记录每次手动回传操作，支持按已确认接口契约进行失败重试。
- 对已确认的接口字段、Payload 规则和数据映射进行开发及本地模拟测试；仅将依赖尚未取得的 Ginlong 外部资料的部分列为待办。

### 4.3 本范围外

- 重复实现 Odoo 现有 WMS 的入库、出库、盘点、库存、拣选、发货及主数据业务逻辑；本模块集成并调用现有 Odoo 业务服务。
- Karl Rapp 的 XML 文件解析/生成、VPN、FTP 和 KR Gateway 的部署与接口实现；这些工作属于后续 `karlrapp_gateway` 范围。
- Karl Rapp WMS 的内部作业处理和其可提供的作业事件能力。
- Solis WMS 内部的 SAP 过账实现。
- 未经双方确认的额外业务接口、字段和状态。

## 6. 业务需求

### 6.1 业务规则

1. 收货确认和入库完成是两个不同业务节点，系统不得将一个节点自动解释为另一个节点。
2. 备货完成和实际发货完成是两个不同业务节点，系统不得将备货完成直接视为实际发货完成。
3. **请求接收、Odoo 业务处理和结果回传是三个不同状态。** 收到请求只表示 Odoo 已接收，不代表业务处理完成；业务处理完成也不代表 Ginlong 已接收回传结果。
4. V3.1 指出待入库单、待出库单和盘点单的修改采用删除后新增的处理方式。`ginlong_apis` 应调用现有 Odoo 业务服务处理相应操作，不在集成层重复实现 WMS 业务状态和库存规则。
5. 02、04、06、08、10 接口的每次回传（包括失败后的重试）均由用户在对应 Odoo 业务单据上手动点击按钮触发。不得因单据状态变化、定时任务、后台重试或其他自动化流程自动发起回传。
6. 对 02/04/06/08/10 回传，本期仅执行权限、安全、数据完整性和格式校验，不执行未在本条列明的业务状态拦截或其他额外业务检查。新增业务检查条件必须通过需求变更追加并批准；不属于本 v1.0 基线，也不阻塞本次冻结。
7. 每次手动回传都应单独记录操作及结果。失败应支持用户再次点击按钮发起重试；重复回传及结果未知时的处理按已确认契约执行，未确认的规则列为待决事项。
8. 对重复请求、部分处理、删除/撤销及失败情况保留可核对结果；不得由集成层假设未确认的业务键、批次完成语义或库存处理规则。

### 6.2 功能需求

以下方向基于 V3.1 的“数据发起方/数据接收方”栏；接口 03 标注为 A-003 开发假设，不视为 Ginlong 已确认的外部契约。详细字段见来源工作簿的接口逻辑和“对接字段”工作表。

| ID | 接口 | 方向（草案） | 需求 |
| --- | --- | --- | --- |
| FR-GIN-001 | 01 待入库单 | Solis → Odoo | Odoo 应接收入库单创建和删除请求，并处理货主、入库单号、仓库、业务类型、备注及产品明细。创建时以入库单号作为单据标识；其唯一性及删除限制按最终确认的接口/业务契约执行。来源资料规定修改按删除后新增处理，集成层应调用现有 Odoo 业务服务处理。 |
| FR-GIN-002 | 02 收货确认 | 用户手动触发，Odoo → Solis | 用户可在对应 Odoo 业务单据上点击回传按钮。按钮应调用本接口，依据现有 Odoo 业务服务及确认的字段规则生成 Payload，并记录操作人、操作时间、Payload/关联信息及回传结果。该操作不得自动触发。仅执行 BR 6.1.6 规定的校验。 |
| FR-GIN-003 | 03 待出库单 | 开发假设：Solis → Odoo（A-003） | 按 A-003 开发假设接收待出库单创建/删除请求，处理客户、地址、收货人、联系方式、发运方式及产品/包装明细，并调用现有 Odoo 业务服务。该方向不是已确认的 Ginlong 外部契约；修改按删除后新增的语义须经 Ginlong 确认后实施。 |
| FR-GIN-004 | 04 入库完成 | 用户手动触发，Odoo → Solis | 用户可在对应 Odoo 业务单据上点击回传按钮。按钮应调用本接口，依据现有 Odoo 业务服务及确认的字段规则生成 Payload，并记录操作人、操作时间、Payload/关联信息及回传结果。该操作不得自动触发。仅执行 BR 6.1.6 规定的校验。来源资料提到支持部分过账；每批数据的唯一标识、部分/整单完成语义及撤销方式待确认。 |
| FR-GIN-005 | 05 盘点单 | Solis → Odoo | Odoo 应能接收盘点单创建和删除请求，并处理盘点单号、仓库、备注及产品/SN/数量/托盘明细。来源资料规定修改按删除后新增处理；删除限制和盘点开始后的改单规则待确认。 |
| FR-GIN-006 | 06 备货完成 | 用户手动触发，Odoo → Solis | 用户可在对应 Odoo 业务单据上点击回传按钮。按钮应调用本接口，依据现有 Odoo 业务服务及确认的字段规则生成 Payload，并记录操作人、操作时间、Payload/关联信息及回传结果。该操作不得自动触发。仅执行 BR 6.1.6 规定的校验。备货完成不得由集成层解释为实际发货完成。分批数据和撤销规则待确认。 |
| FR-GIN-007 | 07 物料档案 | Solis → Odoo | Odoo 应能接收物料新增和修改数据，处理货主、产品编码、名称、规格型号、单位、功率、标准、认证型号、产品形态及尺寸/重量等来源字段。来源资料以“货主 + 物料编码”为唯一键，并描述约每 10 分钟推送最近 1 小时内的变更；停用/删除和重复/迟到数据规则待确认。 |
| FR-GIN-008 | 08 发货完成 | 用户手动触发，Odoo → Solis | 用户可在对应 Odoo 业务单据上点击回传按钮。按钮应调用本接口，依据现有 Odoo 业务服务及确认的字段规则生成 Payload，并记录操作人、操作时间、Payload/关联信息及回传结果。该操作不得自动触发。仅执行 BR 6.1.6 规定的校验。取消、分批及库存记账规则待确认，集成模块不得重复实现库存扣减。 |
| FR-GIN-009 | 09 库存查询 | Solis → Odoo | Odoo 应能按确认的请求条件返回第三方仓库存信息。来源字段包括货主、仓库、产品编码和数量，并包含返回状态、异常信息和操作时间等回执字段。库存状态、数量口径、快照时间和分页规则待确认。 |
| FR-GIN-010 | 10 盘点完成 | 用户手动触发，Odoo → Solis | 用户可在对应 Odoo 业务单据上点击回传按钮。按钮应调用本接口，依据现有 Odoo 业务服务及确认的字段规则生成 Payload，并记录操作人、操作时间、Payload/关联信息及回传结果。该操作不得自动触发。仅执行 BR 6.1.6 规定的校验。部分采集、差异口径、最终完成和撤销规则待确认；盘点业务及库存调整由现有 Odoo 业务服务负责。 |

### 6.3 异常与人工恢复需求

1. 系统应分别记录请求接收结果、Odoo 业务处理结果，以及适用时的 Ginlong 回传/确认结果。前一阶段成功不得自动视为后一阶段成功；状态名称、转换及对外响应表达由 TV/TDD 根据最终契约定义。
2. 请求缺少必需数据、数据格式不符合已确认字段契约、请求未通过安全或权限校验时，系统应拒绝处理或回传，并记录可追踪原因。其他业务校验由现有 Odoo 业务服务和已确认业务规则负责；本 SRS 不新增业务状态拦截条件。
3. 失败或结果未知的请求/回传应保留与接口编号、业务单号或事件标识、操作人（适用时）及处理时间的关联，供授权人员查看和恢复。
4. 对 02/04/06/08/10，每次手动回传应记录一次操作、Payload/关联信息及结果；失败应支持用户再次点击对应按钮重试，后台不得自动重试。重复回传、幂等键、未知结果的核实与重试策略按已确认契约执行；未定义部分列为待决事项，不由本 SRS 预设。
5. 请求接收、业务处理及回传采用同步还是异步模式待决；无论最终模式如何，均应能区分并追踪上述阶段的结果。
6. V3.1 提到接口异常时部分流程可采用 Excel 导入/导出。本能力不属于本 SRS v1.0 冻结范围；如业务方后续要求纳入，须通过需求变更评审其范围、模板和人工审核流程。

## 7. 数据需求

### 7.1 已出现的主要业务字段

| 数据类别 | 字段示例 |
| --- | --- |
| 货主/仓库 | `owner`, `warehouse` |
| 业务单据 | `inboundOrderNo`, `outboundOrderNo`, `countOrderNo`, `action`, `businessType`, `remark` |
| 产品 | `productCode`, `productName`, `specificationModel`, `unit`, `power`, `nationalStandard`, `certificationModel`, `productForm` |
| 数量/包装 | `quantity`, `productSN`, `palletCode`, `palletQty`, `totalWeight` 及出库包装尺寸/重量字段 |
| 收货/发运 | `customer`, `address`, `consignee`, `contact`, `contactEmail`, `shippingMethod` |
| 作业结果 | `operator`, `operationTime`, `receiptConfirmed`, `shipmentConfirmed`, `returnStatus`, `exceptionInfo` |

本节是字段类别摘要，不替代 V3.1 工作簿中的逐接口字段表。必填性、类型、长度、枚举、单位和兼容规则需要 Ginlong 正式 API 文档确认。

### 7.2 数据保留与审计

- 每个请求/回传结果应能追溯至来源系统、接口编号、业务单号或事件标识及处理时间。
- 复用现有 `worlddepot` API 日志能力记录 Ginlong 接收请求及其处理结果；02/04/06/08/10 的每次用户触发、重试和回传结果也须记录，并能关联接口编号、业务单据和操作人。若现有日志字段不足，应在现有日志能力上扩展，不另建平行日志体系。
- API Secret、Access Token、Authorization Token、签名密钥等认证凭据不得写入 API/应用日志。业务 Payload 不作整体脱敏；仅对经数据保护要求认定须保护的个人或敏感字段按批准规则遮蔽或限制访问，并保留排障、审计所需的业务数据。
- 原始报文、处理结果和错误信息的保存范围及期限待双方数据治理要求确认。

## 9. 接口与外部依赖

本 SRS 只定义业务接口行为、边界和验收目标。具体协议和技术实现细节（包括 URL、HTTP 方法、请求头、编码、鉴权、响应/错误码、分页、限流、超时、重试机制、同步/异步交互模式及环境地址）由后续 TV/TDD 根据 Ginlong 正式资料和双方确认结果定义。本 SRS 不对尚未确认的协议细节作决定。已确认的字段与业务契约可先开发并在本地模拟验收；仅依赖缺失资料的实现和真实环境联调受阻。

## 10. 验收范围

验收分为本地模拟验收和真实环境联调验收。已确认的接口契约可先按本地模拟场景开发和验收；缺失外部资料只阻塞依赖该资料的部分。具体协议断言和 Ginlong 侧预期结果须在正式接口文档确认后补全。

**本地模拟验收（不依赖 Ginlong 实际环境）：**

1. 覆盖 01–10 已确认的字段来源、字段映射和数据准备；对尚未确认的字段规则使用模拟契约，不将其作为最终外部契约。
2. 验证 01/03/05/07/09 请求由集成入口接收，并调用 Odoo 现有业务服务或库存服务；业务和库存作业规则不在集成层另行实现。
3. 验证 02/04/06/08/10 的每次回传（含重试）只能由用户点击对应 Odoo 业务单据按钮触发；按钮调用对应接口、生成 Payload 并记录操作及结果；状态变化、定时任务、后台重试或其他自动化不得触发回传。
4. 验证权限、安全、数据完整性和格式校验，并验证回传操作可追溯、失败可重试；重复回传和结果未知场景按已确认契约覆盖，未确认行为保持为待决，不作为本地验收的预设规则。
5. 分别验证请求接收、业务处理及结果回传状态，确保一个阶段成功不会被显示为其他阶段成功；同步/异步交互模式留待 TV/TDD 确认。

**真实环境联调验收（依赖 Ginlong 资料及测试环境）：**

6. 逐接口验证经批准的 URL、鉴权、请求/响应格式、错误码、超时和重试契约，以及 Ginlong 实际处理与确认结果。
7. 验证部分作业、重复回传、结果未知、取消/撤销等场景；仅按双方已确认的业务规则和契约判定通过条件。
8. 验证物料新增/修改和库存查询的关联字段、查询条件及数量口径符合双方确认结果。
9. 双方联调记录请求关联标识、预期结果和实际结果；正式验收由授权业务负责人签署。

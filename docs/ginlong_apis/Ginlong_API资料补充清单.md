# Ginlong API 资料补充清单

**状态：Draft，待 Ginlong 确认**

**适用范围：Ginlong/Solis WMS 与 BeeSmart Odoo 的 API 对接**

**依据：** `海外WMS与第三方系统集成V3.1.xlsx`、`锦浪海外仓接口.drawio`

本清单用于向 Ginlong 收集正式接口合同和联调条件。已有资料描述了业务接口、触发逻辑和部分字段，但尚不足以确定可实施的 HTTP API 契约。未确认项不应按猜测实现。

## 1. 项目范围与系统边界

- [ ] **确认“第三方 WMS”的定义。** 接口资料中的“第三方系统 / 3rd Party WMS”具体指 BeeSmart Odoo、Karl Rapp WMS，还是经 Gateway 对外呈现的仓库系统？确认 Solis 实际调用和接收数据的系统边界。
- [ ] **确认首期接口范围。** 资料列出接口 01–10，请确认本期必做接口、暂缓接口及各接口的业务负责人。
- [ ] **确认接口 03 方向。** Excel 的中文用途说明写 Solis 推送待出库单；英文用途说明写第三方 WMS 推送到 Solis；发起方/接收方栏则显示 Solis → 第三方 WMS。请 Ginlong 给出唯一的正式方向和调用时序。
- [ ] 确认接口版本、适用仓库/货主、兼容策略、版本变更通知方式及技术联系人。

## 2. 全局 API 技术资料

- [ ] **正式 API 文档**：每个接口的 URL/路径、HTTP 方法、请求方向、Content-Type、字符编码、JSON 格式及版本。
- [ ] **环境与地址**：开发/测试/UAT/生产的 Base URL、仓库到 endpoint 的映射、域名/IP、端口、DNS 和环境切换规则。
- [ ] **鉴权与传输安全**：认证方式及完整流程（如 API Key、签名、OAuth、mTLS 等）、签名算法与字段、时间戳/nonce 规则、凭据轮换方式、证书和 IP 白名单要求。测试与生产凭据需分开提供，并通过安全渠道交付。
- [ ] **请求和响应约定**：完整成功、业务失败、系统失败、参数校验失败、重复请求和部分成功的 HTTP 状态码、响应字段、错误码表及可重试标识。
- [ ] **超时与重试**：连接/读取超时建议、Ginlong 的重试次数与间隔、最大重试窗口、重复请求处理、幂等键及请求顺序要求。
- [ ] **流量限制**：请求频率、并发数、批次/数组上限、单报文大小限制、分页/游标规则及限流响应。
- [ ] **关联与追踪**：双方使用的请求 ID、业务单号、事件 ID、回执 ID，以及如何查询单笔请求的处理结果。
- [ ] **时间与数值规范**：时区、日期/时间格式、夏令时处理、数量和重量单位、精度/舍入、空值与零值语义、编码/枚举及字段长度限制。
- [ ] **运行与运维要求**：可用性/SLA、维护窗口、状态页或健康检查、日志/告警联系人及生产问题升级路径。

## 3. 各接口需 Ginlong 提供或确认的内容

请为每个启用接口提供正式请求/响应 Schema、字段必填性和长度/枚举约束，并提供成功、业务失败、重复、部分处理和取消/撤销样例。下表列出需特别确认的业务问题。

| 接口 | 资料/确认项 |
| --- | --- |
| **01 待入库单** | 完整单头和明细字段；创建/删除动作值；唯一键；修改时先删后建的原子性、失败恢复和重放规则；按仓库选择地址的映射；删除前仓库单据允许处于什么状态。 |
| **02 收货确认** | 确认/取消的字段和状态转换；取消能否发生在入库完成之后；回执是否包含实际收货数量、产品、SN/托盘及时间；重复确认的返回规则。 |
| **03 待出库单** | 先解决方向冲突；之后提供最终请求方/接收方、完整字段、动作值、唯一键、修改和删除规则，以及仓库 endpoint 映射。 |
| **04 入库完成** | “收货确认”和“入库完成/上架完成”的区别；是否允许分批回传及每批标识；实际数量、SN、托盘、批次/库位字段；删除/冲销的范围；部分过账后如何补传剩余明细。 |
| **05 盘点单** | 盘点范围、仓库/库位/产品条件、计划数量或盘点方式；创建、删除、修改的动作规则；唯一键和已开始盘点后的变更限制。 |
| **06 备货完成** | 完成事件的粒度；分批备货的批次/事件 ID；实际产品数量、SN、托盘和时间字段；撤销单批结果的方式；备货是否只代表拣货完成而不代表库存扣减。 |
| **07 物料档案** | 完整物料字段、主数据唯一键、必填性和覆盖规则；新增/修改/停用/删除如何表达；“每 10 分钟推送最近 1 小时变更”的时间边界、补偿与重复推送行为。 |
| **08 发货完成** | 发货确认的业务含义；分批发货及每批实际数量/SN/托盘/承运信息；发货时间、取消/冲销及重复确认规则；何时视为库存扣减依据。 |
| **09 库存查询** | 请求筛选字段（仓库、货主、产品、批次/SN、库位等）、分页和查询上限；响应库存口径、可用/冻结等状态、计量单位、库存时间戳和一致性要求。 |
| **10 盘点完成** | 实盘数量/差异字段、产品/SN/托盘/库位粒度、部分提交规则、确认和撤销方式；盘点结果是否由 Solis 入账以及如何回查结果。 |

## 5. 不属于 Ginlong 提供范围的资料

以下内容应向 Karl Rapp 或 Gateway 负责人单独收集，不要求 Ginlong 提供：

- Karl Rapp XML Schema/XSD、真实 XML 样例、文件命名/目录/就绪标识、FTP 行为和作业结果粒度。
- VPN 协议、端点、认证参数、访问网段和允许端口。
- KR Gateway HTTPS API 的路径、鉴权、任务状态、文件上传/下载/确认及错误恢复契约。
- KR 实际作业事件、分批/撤销规则和 KR 库存快照字段。

这些资料决定 Karl Rapp/Gateway 链路的实现，但不替代 Ginlong 与 Odoo 的 API 合同。
